# `extract-contract` 엣지 함수에 이메일 추출 추가하기

Student 360 의 '계약서에서 채우기'가 학생·학부모 이메일을 채우려면,
계약서를 읽는 엣지 함수가 그 두 값을 돌려줘야 한다. 앱·DB 쪽은 이미 준비돼 있다
(`contracts.student_email` / `parent_email`, 업로드 폼 입력칸, 자동 채움 매핑).

고칠 곳은 `supabase/functions/extract-contract/index.ts` 의 `SYSTEM_PROMPT` 한 군데다.
요청·응답 구조는 건드리지 않는다 — 앱은 모르는 키가 와도 무시하고,
안 오는 키는 null 로 채운다(`extract-contract-ai.ts` 의 `EMPTY_RESULT` 병합).

---

## 1) 필드 목록에 두 줄 추가

`- phone: ...` 줄 바로 아래에 붙인다.

```
- studentEmail: 학생 본인의 이메일 주소. 없으면 null
- parentEmail: 학부모(계약자)의 이메일 주소. 없으면 null
```

## 2) 규칙에 네 줄 추가

맨 끝 번호에 이어 붙인다(번호는 기존 마지막 번호 다음으로).

```
N. 이메일이 하나만 적혀 있고 누구 것인지 구분이 없으면 parentEmail 에 넣고 studentEmail 은 null 로 두세요. 계약서에 서명하는 쪽은 보통 학부모입니다.
N+1. 퀀텀어드미션즈(공급자) 쪽 이메일은 추출하지 마세요. @quantumadmissions.com 처럼 회사 도메인이거나 '담당자', '컨설턴트', '을(乙)' 란에 적힌 주소는 고객 정보가 아닙니다. 계약자·학생(갑) 쪽 주소만 추출합니다.
N+2. 이메일은 소문자로, 공백 없이 반환하세요. 'abc @ gmail .com' 처럼 띄어 적혀 있으면 'abc@gmail.com' 으로 붙이세요.
N+3. "이메일", "E-mail", "메일주소" 같은 라벨을 값으로 쓰지 마세요. '@' 가 들어간 실제 주소만 값입니다. 확실하지 않으면 null 로 두세요.
```

> 마지막 줄이 중요하다. 추측한 이메일이 들어가면 학생정보에 잘못된 주소가 박히고,
> 그쪽이 빈칸보다 나쁘다 — 자동 채움은 빈칸만 채우므로 한번 잘못 들어가면 덮어쓰지 않는다.

## 3) 프롬프트에 JSON 예시가 있다면 거기에도 추가

```json
"phone": "010-1234-5678",
"studentEmail": "student@example.com",
"parentEmail": "parent@example.com",
```

---

## 확인

1. 계약관리에서 이메일이 적힌 계약서 PDF 를 업로드한다.
2. 추출 결과 폼에 '학생 이메일' / '학부모 이메일' 칸이 채워져 있는지 본다
   (비어 있으면 손으로 적어도 된다 — 칸은 이미 있다).
3. 저장한 뒤 Student 360 에서 그 학생의 '📄 계약서에서 채우기' 를 누르면
   두 이메일이 목록에 나온다.

## 참고 — 함께 보면 좋은 것 (선택)

- 지금 함수는 "반드시 유효한 JSON만 반환하세요" 로 형식을 지시하고 `JSON.parse` 로 받는다.
  Messages API 의 구조화 출력(`output_config.format`)을 쓰면 형식이 보장돼
  파싱 실패 자체가 없어진다. 바꾸려면 요청 본문에 스키마를 넣고 파싱 분기를 지우면 된다.
- 다른 추출 함수(`extract-meeting-note`)는 모델이 `claude-sonnet-4-6-20250627` 로 박혀 있다.
  현재 세대는 `claude-sonnet-5-5` 이고 모델 ID 에 날짜를 붙이지 않는다.
  이번 작업과는 무관하니 필요할 때 따로 보면 된다.
