# CAT 자료 DB (cat-db)

퀀텀어드미션즈 컨설턴트들이 쌓아 온 CAT 자료(문서)를 DB로 만드는 하위 프로젝트입니다.
같은 저장소의 내부 관리 시스템(`../app`, `../supabase`)과는 별개로 진행합니다.

## 목표

- 조건별(학년, 희망 전공, 목표 학교, 프로젝트 유형, 성과)로 관련 사례를 **SQL로 빠르게 조회**하고,
  그 결과를 LLM이 분석해 보고서를 쓰는 데 활용합니다.
- **원본은 원본 자리에 둡니다**(구글 드라이브 등). DB에는 원본 위치(URL/파일 ID)와 태그만 저장합니다.
- 나중에 웨비나 녹음과 인스타 영상(전사본)도 **같은 구조**로 넣을 수 있게 설계합니다.
  `source_type`으로 구분하고, 태그 테이블은 함께 씁니다.

## 핵심 설계 원칙 (변경 시 ADR 필수)

1. **태그 체계를 먼저 확정합니다.** 대상은 학생 정보, 프로젝트 유형, 잘한 점/문제점, 컨설턴트 코멘트, 결과 지표입니다.
   태그 사전(`taxonomy/`)이 정본이고, DB 스키마는 이 사전을 따릅니다.
2. **성과는 시점별로 저장합니다.** 최종 합격 결과는 3~4년 뒤에 나오므로 1·2·3년차 중간 평가를
   별도 행으로 저장합니다. 그래야 "성공 사례만 벤치마크"하는 조회가 가능합니다.
   평가 기준(루브릭)은 `taxonomy/`에 버전을 붙여 관리합니다.
3. **개인정보는 가명 처리합니다.** 모든 테이블은 학생 ID(예: `STU-0001`)만 사용합니다.
   실명 대조표는 `private/`에만 두고, **절대 커밋하지 않습니다.**

## 진행 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1단계 | 샘플 자료로 태그 체계와 테이블 구조 설계 | 🔄 태그 v0.2와 스키마 002 초안 작성, 사용자 검토 대기 |
| 2단계 | 샘플 30건 안팎으로 파일럿 구축 및 조회 테스트 | 대기 |
| 3단계 | 전체 자료 일괄 처리 및 정기 운영 자동화 | 대기 |

단계를 넘어갈 때마다 이 표를 갱신합니다.

## 폴더 구조

```
cat-db/
├── CLAUDE.md              # 이 파일. 프로젝트 규칙과 현재 상태
├── README.md              # 사람용 개요와 실행 방법
├── docs/
│   ├── WORKLOG.md         # 작업 히스토리 (세션마다 추가)
│   └── decisions/         # ADR: 설계 결정 기록 (NNNN-제목.md)
├── taxonomy/              # 태그 사전(.yaml이 정본, .md는 검토용 자동 생성), 성과 루브릭
├── schema/                # DDL (NNN_설명.sql 순서대로 적용)
├── queries/               # 자주 쓰는 조회 SQL (벤치마크, 조건 검색 등)
├── scripts/               # 추출, 태깅, 적재, 동기화 스크립트
├── samples/redacted/      # 지식 자료(A층) 샘플·합성 테스트 데이터만. 학생 사례는 가명이어도 금지
├── data/raw/              # 원본 사본/추출본. git 제외
└── private/               # 실명 대조표, 비밀키. git 제외
```

## 작업 규칙

- **개인정보**
  - 학생 실명, 학부모 이름, 연락처, 이메일, 재학 학교+학년 조합처럼 개인을 특정할 수 있는 정보를
    커밋, 문서, 커밋 메시지, 로그에 남기지 않습니다.
  - 샘플을 분석할 때도 결과물에는 학생 ID만 씁니다.
  - **학생 사례(B층)에서 나온 데이터는 가명 처리했더라도 커밋하지 않습니다.** 상담 내용, 추출 JSON, 태깅 결과 모두 `data/raw/`나 DB에만 둡니다. 문서에는 양식과 구조만 적고, 개별 학생의 내용은 옮기지 않습니다.
  - 학생 개인정보는 회사가 승인한 AI 도구에만 입력합니다(운영 매뉴얼 5.8). 실명은 LLM에 넣기 전에 제거합니다.
  - 원본 자료는 `data/raw/`에, 대조표는 `private/`에 둡니다. 두 폴더 모두 `.gitignore` 처리되어 있습니다.
  - 커밋 전에 `git status`로 이 폴더들이 빠졌는지 확인합니다.
- **작업 히스토리**
  - 의미 있는 작업을 마치면 `docs/WORKLOG.md` 맨 위에 날짜, 한 일, 결정, 다음 할 일을 추가합니다.
  - 태그 체계나 스키마, 원칙을 바꾸는 결정은 `docs/decisions/`에 ADR로 남깁니다.
    배경, 선택지, 결정, 영향을 적습니다.
  - 커밋 메시지는 저장소 관례를 따릅니다(`feat(cat-db): ...`, `fix(cat-db): ...`, `docs(cat-db): ...`).
- **스키마**
  - DDL은 `schema/`에 번호를 붙여 추가만 합니다. 이미 적용한 파일은 고치지 않고 새 마이그레이션을 씁니다.
  - 태그 사전을 고치면 `python3 scripts/render_taxonomy.py taxonomy/tags-vX.yaml > taxonomy/tags-vX.md`로 검토용 표도 갱신합니다. 현재 버전은 v0.2입니다.
  - 태그 값은 자유 텍스트가 아니라 `taxonomy/` 사전의 코드로 저장합니다.
    사전에 없는 값이 나오면 먼저 사전에 추가하고 ADR이나 WORKLOG에 기록합니다.
- **LLM 활용**
  - 원문 추출과 태깅은 LLM으로 할 수 있습니다.
  - 태그 결과에는 `tagged_by`(llm/human), `confidence`, `taxonomy_version`을 함께 저장해서 사람이 검수할 수 있게 합니다.

## 미결 사항

- **B층(학생 사례) 원천 자료**: 내부 포털(`service_students`, `service_meetings.report_url` 등)이 원천. 가명화해서 받는다 → ADR 0003, `docs/case-source-review-2026-10-01.md`
- 보고서 태깅용 LLM을 운영 매뉴얼 11.12 승인 AI 도구 목록에 등록할지

- DB 엔진: 파일럿은 SQLite(설치 불필요), 운영은 기존 Supabase(Postgres)로 이전하는 방안을 제안했습니다.
  1단계에서 확정합니다. → `docs/decisions/0001-db-engine.md`
- 원본 저장소(구글 드라이브 폴더 구조, 파일 ID 사용 여부)
- 성과 점수 루브릭(1·2·3년차 평가 항목과 척도): 사내 평가 제도는 아직 없고 회사 웹사이트에서 구축 중. 웹사이트 평가 데이터를 받는 형태로 맞춘다
