# 0002. 지식 자료(A층)와 학생 사례(B층)를 분리하되 원본·태그는 공유

- 날짜: 2026-10-01
- 상태: 제안

## 배경
첫 샘플 폴더(152개 PDF)는 학부모 대상 가이드북 중심이었다. 학생 단위 기록, 컨설턴트 코멘트, 연차별 평가가 없다. 그런데 원래 목표(조건별 사례 조회, 성공 사례 벤치마크)는 학생 단위 데이터가 있어야 성립한다.

## 선택지
1. 가이드북을 학생 사례처럼 억지로 태깅 → 학생·성과 칸이 비어 조회 가치 없음
2. 학생 사례 자료만 DB화 → 이미 쌓인 152개 지식 자료를 활용하지 못함
3. 두 층으로 분리하고 `sources`(원본 위치)와 `tags`(태그 사전)는 공유

## 결정 (제안)
3번.
- `sources`: 모든 원본(PDF, 문서, 웨비나 녹음, 인스타 영상)의 위치·해시·유형을 저장
- A층: `sources` + `source_tags` 만으로 조회 (예: "11학년 · 바이오 · 여름프로그램" 자료)
- B층: `students`(가명) → `projects` → `evaluations`(연차별) / `outcomes`(최종), 그리고 근거가 된 원본은 `sources`로 연결
- 태그 사전 하나를 양쪽에서 씀 → "바이오 전공 성공 사례 + 관련 가이드"를 한 번에 조회 가능

## 영향
- B층 원천 자료(컨설팅 기록, 합격자 원서, 상담 노트 등)의 형태 확인이 필요
- A층은 B층과 무관하게 먼저 파일럿 가능
